# F-023 — Nom de fichier long : erreur 500 à l'envoi d'un document

- **Gravité** : Basse
- **Exigence** : SEC-06
- **Trouvée par** : attaquant, manche 2, le 2026-11-27
- **Route / fichier** : `POST /matieres/<id>/documents` — `backend/services/subject_service.py:111-112`
- **Statut** : ferme

## Reproduction

Le chemin stocké est `<uuid de 32 caractères>_<secure_filename(nom d'origine)>`, sans raccourcir le nom.

1. Envoi de `"a" * 250 + ".txt"`, `"e" * 240 + ".md"`, `"x" * 195 + ".html.txt"`.

Résultat observé : 500 (`FileNotFoundError` sous Windows, chemin de plus de 260 caractères ; sous Linux le nom
dépasse 255 octets dès ~222 caractères : `OSError: File name too long`).

Résultat attendu : nom stocké raccourci, envoi accepté ou refusé proprement, jamais de 500.

Conforme (testé) : traversée de chemin (`../../etc/passwd.txt`, `..\..\evil.txt`, `/etc/passwd.md`,
`C:\Windows\evil.txt`, `%2e%2e%2f`, octet nul) : tout reste dans `UPLOAD_FOLDER/<user_id>/`.

## Correction (rempli par le défenseur)

- Fichiers modifiés : `backend/business/uploads.py` (`stored_name`), `backend/services/subject_service.py` (`_stored_path`, utilisé par `save_documents` et `save_photos`)
- Principe : nom stocké = UUID + `_` + nom d'origine passé par `secure_filename`, raccourci à 80 caractères, extension (10 caractères au plus) conservée pour le choix du lecteur. Le nom d'origine complet reste affiché (colonne `filename`, 200 caractères).
