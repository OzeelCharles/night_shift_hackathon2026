# F-019 — Pas de quota de stockage par utilisateur

- **Gravité** : Basse
- **Exigence** : SEC-06
- **Trouvée par** : attaquant, manche 2, le 2026-11-27
- **Route / fichier** : `POST /matieres/<id>/documents` — `backend/services/subject_service.py:102` (`save_documents`)
- **Statut** : ouvert (contournement non corrigé, duel arrêté)

## Reproduction

1. Un utilisateur envoie 9 fichiers `.txt` de 24 Mo (sous la limite de 25 Mo par requête).
2. Les 9 sont acceptés : **216 Mo** stockés pour un seul compte.

Impact : remplissage du disque par un compte (ou plusieurs, l'inscription étant libre), donc indisponibilité
pour tous. Gravité Basse : l'attaquant doit réellement envoyer les données.

Résultat attendu : quota de 200 Mo de documents par utilisateur ; l'envoi qui le dépasse est refusé avec un message.

## Test qui reproduit

- `backend/tests/security/test_sec_06_fichiers.py::QuotaTests::test_quota_de_200_mo_par_utilisateur`

(échoue avant la correction)

## Correction (rempli par le défenseur)

- Fichiers modifiés : `backend/business/uploads.py` (nouveau : `USER_QUOTA_BYTES`, `over_quota`), `backend/services/subject_service.py` (`save_documents`, `_used_bytes`, `_stream_size`)
- Principe : avant d'enregistrer un fichier, le service additionne la taille des fichiers déjà stockés dans le dossier de l'utilisateur et celle du fichier envoyé (mesurée sur le flux). Si le total dépasse 200 Mo (surchargeable par `USER_QUOTA_BYTES` dans la config), le fichier est refusé avec un message et rien n'est écrit.
