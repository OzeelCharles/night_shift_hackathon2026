# F-026 — Retour à la ligne dans `next` : erreur 500

- **Gravité** : Basse
- **Exigence** : SEC-04
- **Trouvée par** : attaquant, manche 2, le 2026-11-27
- **Route / fichier** : `POST /connexion?next=...` — `backend/controllers/auth.py` (`redirect(safe_next(...))`)
- **Statut** : ferme

## Reproduction

1. `POST /connexion?next=/%0d%0aSet-Cookie:%20pirate=1` avec des identifiants valides.
2. `safe_next` accepte la valeur ; Werkzeug refuse d'écrire un en-tête qui contient un retour à la ligne :
   `ValueError: Header values must not contain newline characters.` → **500**.

Pas d'injection d'en-tête (Werkzeug bloque), mais une erreur serveur déclenchable par un simple lien.

Résultat attendu : valeur refusée par `safe_next`, redirection vers la page par défaut.

## Test qui reproduit

- `backend/tests/security/test_sec_04_csrf_redirections.py::RedirectionsTests::test_injection_d_en_tete_par_next`

(échoue avant la correction)

## Correction (rempli par le défenseur)

- Fichiers modifiés : `backend/core/security.py` (`safe_next`)
- Principe : même correction que F-025 : une valeur qui contient CR/LF (ou tout caractère de contrôle, même encodé) est refusée par `safe_next` et remplacée par la page par défaut. Werkzeug ne reçoit plus d'en-tête invalide, donc plus de 500.
