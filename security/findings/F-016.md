# F-016 — Session non invalidée au changement de mot de passe, durée de vie de 31 jours

- **Gravité** : Moyenne
- **Exigence** : SEC-03
- **Trouvée par** : attaquant, manche 1, le 2026-11-27
- **Route / fichier** : `POST /admin/utilisateurs/<user_id>` (champ `password`) — `backend/core/security.py` (`load_current_user`), `backend/config.py` (pas de `PERMANENT_SESSION_LIFETIME`)
- **Statut** : ferme

## Reproduction

1. L'élève se connecte ; l'attaquant copie son cookie de session (vol de cookie).
2. L'admin change le mot de passe de l'élève (seul moyen de reprendre un compte compromis : pas de changement
   de mot de passe en libre-service).
3. L'attaquant rejoue l'ancien cookie sur `/tableau-de-bord` : 200, toujours connecté.
4. Variante : rejeu du cookie avec une horloge avancée de 8 jours (`time.time` simulé) : 200. Flask applique par défaut
   une durée de 31 jours à la signature du cookie ; le cahier en demande 7.

Résultat observé : le cookie volé reste valide après le changement de mot de passe et au-delà de 7 jours.

Résultat attendu : un changement de mot de passe invalide les sessions existantes (compteur de version de session
dans `users`) ; une session expire après 7 jours.

Conforme (testé) : la session est régénérée à la connexion (pas de fixation) ; la désactivation d'un compte coupe
immédiatement l'ancien cookie.

## Correction (rempli par le défenseur)

- Fichiers modifiés : `backend/config.py` (`PERMANENT_SESSION_LIFETIME` = 7 jours), `backend/dao/db.py` (migration 2 : `users.session_version`), `backend/dao/users.py` (`bump_session_version`), `backend/core/security.py` (`start_session`, contrôle dans `load_current_user`), `backend/services/admin_service.py`, `backend/controllers/auth.py`, `backend/controllers/admin.py`, `backend/tests/test_migration_sessions.py` (nouveau)
- Principe : la session (régénérée à la connexion et à l'inscription par `start_session`) porte la version de session du compte et l'heure de connexion ; `load_current_user` la refuse si la version diffère, si le compte est désactivé ou si la connexion date de plus de 7 jours (en plus de la signature limitée à 7 jours par Flask). Un changement de mot de passe ou une désactivation incrémente `session_version` : tous les cookies existants tombent. Migration 2 additive (`ALTER TABLE users ADD COLUMN session_version INTEGER NOT NULL DEFAULT 0`), réversible par `DROP COLUMN`, testée sur une base v1 avec données.
