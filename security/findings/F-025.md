# F-025 — Redirection ouverte après connexion (`next=/%09/evil.com`)

- **Gravité** : Moyenne
- **Exigence** : SEC-04
- **Trouvée par** : attaquant, manche 2, le 2026-11-27
- **Route / fichier** : `POST /connexion?next=...`, `POST /profil/infos` (`next`), `POST /campus/signaler` (`back`) — `backend/core/security.py:61` (`safe_next`)
- **Statut** : ferme

## Reproduction

`safe_next` accepte toute valeur qui commence par `/` sans commencer par `//`.

1. La victime suit `https://<site>/connexion?next=/%09/evil.com` et se connecte.
2. `request.args` décode `%09` en tabulation : `safe_next("/\t/evil.com")` l'accepte.
3. Werkzeug retire la tabulation en écrivant l'en-tête : **`Location: //evil.com`** (vérifié dans le test).
   Le navigateur part sur `evil.com` juste après une connexion réussie : page de phishing crédible
   (« session expirée, reconnecte-toi »).

Même chose avec `next` de `/profil/infos` et `back` de `/campus/signaler`.

Écart supplémentaire au critère du cahier (« `safe_next` refuse les 5 charges ») : `safe_next` accepte aussi
`/\evil.com`, `/admin/..//evil.com`, `/\/evil.com`, `/%5Cevil.com`. Werkzeug encode ensuite `\` en `%5C`, ce qui
les neutralise aujourd'hui, mais sans que ce soit voulu.

Résultat attendu : `safe_next` n'accepte qu'un chemin interne normalisé (refus des caractères de contrôle, de `\`,
de `//` après normalisation) ; aucun `Location` qui mène hors du site.

Conforme (testé) : `//evil.com`, `https://evil.com`, `%2F%2Fevil.com`, `javascript:` refusés ; le retour admin
(`/admin/../\evil.com`…) reste sur le site. CSRF : tous les POST de `app.url_map` répondent 400 sans jeton,
avec un jeton vide, avec le jeton (champ ou en-tête) d'une autre session ; aucune route GET ne modifie la base.

## Correction (rempli par le défenseur)

- Fichiers modifiés : `backend/core/security.py` (`safe_next`, `_internal_path`)
- Principe : `safe_next` n'accepte qu'un chemin interne simple : un seul « / » au début, aucun antislash ni caractère de contrôle (`\x00`-`\x1f`, `\x7f`), pas de « // » ni de segment « . » / « .. » dans le chemin. La même vérification porte sur la valeur décodée jusqu'à 3 fois (`%5C`, `%09`, `%2F%2F`…). Toutes les routes qui suivent un `next` ou un `back` passent par cette fonction (connexion, `/profil/infos`, agenda, planning, campus).
