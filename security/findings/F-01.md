# F-01 — SSRF en lecture complète par le lien d'une offre de stage

- **Gravité** : Haute (CVSS 3.1 indicatif : AV:N/AC:L/PR:L/UI:N/S:C/C:H/I:N/A:N ≈ 7.7)
- **Exigence** : SEC-07
- **Trouvée par** : attaquant, manche 1, le 2026-11-27
- **Route / fichier** : `POST /stages/offres` — `backend/plugins/stages/service.py:111` (`_fetch`), `:119` (`secure_session().get`), `:133` (`add_offer`)
- **Statut** : ferme

## Reproduction

1. Un utilisateur simple se connecte (inscription libre).
2. Il envoie `POST /stages/offres` avec seulement `url=<adresse interne>` (sans titre ni description).
3. `add_offer` appelle `_fetch(url)`, qui fait un `GET` sans aucun contrôle d'hôte, de port ni de redirection
   (`requests` suit les redirections par défaut), puis `parse_offer` extrait titre, entreprise et description de la page.
4. Le contenu de la page interne est enregistré dans l'offre et réaffiché à l'utilisateur.

Charges utilisées (serveur local 127.0.0.1 qui compte les requêtes, garde réseau qui bloque tout le reste) :
`http://127.0.0.1:<port>/admin`, `http://localhost:<port>/admin`, `http://[::1]:<port>/admin`, `http://0x7f000001:<port>/admin`,
`http://2130706433:<port>/admin`, `http://127.1:<port>/admin`, `http://[::ffff:127.0.0.1]:<port>/admin`, `http://0.0.0.0:<port>/admin`,
`http://169.254.169.254/latest/meta-data/`, `http://10.0.0.1/`, `http://192.168.1.1/admin`, `http://172.16.0.1/`, `http://[fd00::1]/`,
`http://100.64.0.1/`, et un hôte « public » simulé (`offres-publiques.example` → 8.8.8.8) qui répond `302 Location: http://127.0.0.1:<port>/admin`.

Résultat observé : le serveur interne reçoit `GET /admin` ; l'offre est enregistrée avec
`title = "PAGE-INTERNE-SECRETE"`, `company = "Intranet"`, `description = "jeton-interne-0123456789"` (contenu de la page interne),
affichés à l'attaquant. Une connexion part vers chaque adresse privée / métadonnées cloud. La redirection publique → 127.0.0.1 est suivie.

Résultat attendu : lien refusé, aucune connexion vers une adresse non publique (y compris après redirection), aucune offre enregistrée.

Non vulnérable (testé, conforme) : `file://`, `gopher://`, `ftp://`, `dict://` sont refusés avant toute connexion.

Remarque : le téléchargement n'a lieu que si `ENABLE_WEB` est vrai, ce qui est la valeur par défaut (`backend/config.py`).

## Correction (rempli par le défenseur)

- Fichiers modifiés : `backend/dao/safe_http.py` (nouveau), `backend/plugins/stages/service.py` (`_fetch`), `backend/tests/test_safe_http.py` (nouveau), `backend/tests/test_stages.py` (mock déplacé de `web.secure_session` vers `safe_http.get`)
- Principe : tout lien fourni par un utilisateur est téléchargé par `safe_http.get()` : http/https seulement, ports 80/443, pas d'identifiants dans l'URL ; résolution unique du nom et refus si une seule adresse n'est pas publique (`is_global`, multicast, non spécifiée, IPv4 mappée/6to4/Teredo vers une adresse interne) ; connexion à l'IP vérifiée (connexions `http.client` épinglées, certificat TLS vérifié pour le nom demandé) ; au plus 3 redirections, chacune revérifiée comme une nouvelle URL ; 5 Mo et 10 s au total. `_fetch` n'utilise plus `requests` : un refus donne « offre illisible », rien n'est enregistré sans intitulé.
