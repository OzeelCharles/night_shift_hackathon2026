# F-04 — Énumération de comptes (inscription, compte désactivé, temps de réponse)

- **Gravité** : Moyenne
- **Exigence** : SEC-03
- **Trouvée par** : attaquant, manche 1, le 2026-11-27
- **Route / fichier** : `POST /inscription`, `POST /connexion` — `backend/services/auth_service.py:30`, `:39`, `:42`
- **Statut** : ferme

## Reproduction

1. Inscription avec une adresse déjà utilisée (variantes : `EXISTE@Test.fr`, ` existe@test.fr `) :
   message « Un compte existe déjà avec cette adresse. ».
2. Connexion sur un compte désactivé par l'admin, **avec le bon mot de passe** : message
   « Ce compte a été désactivé par un administrateur. » au lieu de « E-mail ou mot de passe incorrect. ».
   L'attaquant apprend que le compte existe **et** que le mot de passe est juste.
3. Temps de réponse : e-mail inconnu ≈ 1,2 ms, e-mail connu + mauvais mot de passe ≈ 78 ms (médiane de 5 essais,
   client de test local). `check_password_hash` n'est appelé que si le compte existe : l'écart (≈ 77 ms) dépasse
   la tolérance de ± 50 ms du cahier et suffit à trier une liste d'adresses.

Résultat observé : trois oracles d'existence de compte (message d'inscription, message « désactivé », temps de réponse).

Résultat attendu : même message et même temps (± 50 ms) pour un e-mail inconnu, un mauvais mot de passe et un compte
désactivé ; l'inscription ne confirme pas qu'une adresse existe.

## Correction (rempli par le défenseur)

- Fichiers modifiés : `backend/services/auth_service.py` (`authenticate`, `register`)
- Principe : un seul message (« E-mail ou mot de passe incorrect. ») pour e-mail inconnu, mauvais mot de passe et compte désactivé ; le mot de passe est toujours vérifié, contre une empreinte factice de même algorithme si l'e-mail est inconnu (temps égalisé). Inscription : message neutre « Impossible de créer un compte avec ces informations. Si tu as déjà un compte, connecte-toi. », avec un hachage du mot de passe pour un coût identique, et la tentative compte dans la limite de 5 par IP et par heure. Limite résiduelle : sans vérification de l'adresse par e-mail, la réussite ou l'échec d'une inscription reste observable ; la limite par IP la rend coûteuse.
