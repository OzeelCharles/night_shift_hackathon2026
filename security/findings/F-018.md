# F-018 — Type de fichier vérifié par l'extension seule ; documents servis sans nosniff

- **Gravité** : Basse
- **Exigence** : SEC-06
- **Trouvée par** : attaquant, manche 2, le 2026-11-27
- **Route / fichier** : `POST /matieres/<id>/documents`, `GET /documents/<id>` — `backend/business/extractor.py` (`allowed_file`), `backend/controllers/subjects.py:96`
- **Statut** : ferme

## Reproduction

1. Envoi d'une page HTML (`<script>alert(document.cookie)</script>`) sous les noms `cours.pdf`, `cours.docx`,
   `cours.odt`, `cours.pptx` : les 4 sont acceptées et enregistrées (« texte illisible »).
2. `GET /documents/<id>` d'un `.pdf` et d'un `.txt` contenant du HTML : servis **dans le navigateur**
   (`application/pdf`, `text/plain`) **sans** `X-Content-Type-Options: nosniff`.

Impact : les navigateurs actuels n'interprètent pas ces types comme du HTML, d'où la gravité Basse ; mais sans
signature ni nosniff, la protection repose entièrement sur le navigateur.

Résultat attendu : type vérifié par le contenu (`%PDF`, archive ZIP pour Office/ODF), refus sinon ; réponses de
`/documents/<id>` avec `nosniff`.

Conforme (testé) : `.docx` et `.odt` servis en pièce jointe, jamais affichés.

## Correction (rempli par le défenseur)

- Fichiers modifiés : `backend/business/extractor.py` (`check_content`, lecteurs en flux `_docx`, `_pptx`, `_odf`, `_Budget`), `backend/services/subject_service.py` (`save_documents`), `backend/core/security.py` (`no_sniff`)
- Principe : le type est vérifié par le contenu avant l'analyse : signature `%PDF-` pour un PDF ; pour .docx/.pptx/.odt/.odp, une archive ZIP (`PK\x03\x04`) qui contient sa partie principale (`[Content_Types].xml` ou `content.xml`). Sinon le fichier est supprimé et refusé. Toutes les réponses portent `X-Content-Type-Options: nosniff` (`after_request` global), y compris `/documents/<id>`.
