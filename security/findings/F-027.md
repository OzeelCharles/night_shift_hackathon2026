# F-027 — Recherche admin : chaîne longue → erreur 500 (« LIKE pattern too complex »)

- **Gravité** : Basse
- **Exigence** : SEC-01
- **Trouvée par** : attaquant, manche 2, le 2026-11-27
- **Route / fichier** : `GET /admin/?q=...` — `backend/dao/users.py` (`list_with_counts`, `LIKE ?` avec `%{search}%`)
- **Statut** : ferme

## Reproduction

1. Un admin cherche une chaîne de 100 000 caractères (`GET /admin/?q=xxxx…`).
2. SQLite refuse le motif (`SQLITE_LIMIT_LIKE_PATTERN_LENGTH` = 50 000) :
   `sqlite3.OperationalError: LIKE or GLOB pattern too complex` → **500**.

Accessible aux seuls admins (ou via un lien envoyé à un admin) : gravité Basse.

Résultat attendu : `q` tronqué (comme `/api/*`, limité à 80-100 caractères), jamais de 500.

Conforme (testé sur toutes les routes, GET et POST) : aucune injection SQL, aucune trace SQL affichée, aucune table
supprimée, comptes d'autrui intacts, charge stockée telle quelle (paramètres `?`) ; affectation de masse sur
`/profil` et `/profil/infos` sans effet ; jokers `%` et `_` sans fuite dans les API de suggestion ; SQL dynamique
limité aux 17 emplacements relus (listes blanches codées en dur, constat F-13).

## Test qui reproduit

- `backend/tests/security/test_sec_01_injections.py::InjectionsTests::test_charges_dans_les_routes_admin`

(échoue avant la correction)

## Correction (rempli par le défenseur)

- Fichiers modifiés : `backend/controllers/admin.py`, `backend/services/admin_service.py` (`overview`, `SEARCH_MAX`)
- Principe : la recherche `q` de `/admin/` est tronquée à 100 caractères, dans le contrôleur et dans le service (seconde barrière). SQLite ne reçoit jamais un motif LIKE trop long, donc plus de 500. La requête reste paramétrée (`?`).
