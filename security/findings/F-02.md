# F-02 — Rebinding DNS sur le téléchargement de PDF d'exercices

- **Gravité** : Moyenne
- **Exigence** : SEC-07
- **Trouvée par** : attaquant, manche 1, le 2026-11-27
- **Route / fichier** : `POST /reviser/<subject_id>/exercices` (via `_collect_online`) — `backend/plugins/revision/sources.py:46` (`_public_host`), `:52` et `:62`
- **Statut** : ferme

## Reproduction

1. `pdf_text(url)` vérifie l'hôte avec `_public_host()` : `socket.getaddrinfo(hôte)` → toutes les adresses sont publiques.
2. Puis `requests.get(url, ...)` résout **à nouveau** le nom et se connecte à la nouvelle adresse, sans revérification.
3. Un domaine contrôlé par l'attaquant (TTL 0) répond d'abord une IP publique, puis `127.0.0.1` : le contrôle passe
   et la connexion part vers la boucle locale.

Charge utilisée : DNS factice `rebind.example` → `8.8.8.8` au 1er appel, `127.0.0.1` ensuite ; un service interne simulé
sur `127.0.0.1:80` (détourné vers un serveur local qui compte les requêtes). Appel `pdf_text("http://rebind.example/cours.pdf")`.

Résultat observé : le service interne reçoit `GET /cours.pdf` (connexion vers `127.0.0.1:80`).

Résultat attendu : une seule résolution, connexion à l'adresse vérifiée (ici l'IP publique), aucune connexion vers 127.0.0.1.

Non vulnérable (testé, conforme) : `127.0.0.1`, `[::1]`, `169.254.169.254`, nom résolu en `10.x`, `file://`, `2130706433` sont refusés
sans connexion. Les redirections ne sont pas suivies (`allow_redirects=False`).

Exploitation réelle : l'URL vient des résultats de recherche web ou des ressources de type `web`/`exam` d'une matière ;
l'attaquant doit faire apparaître son lien dans ces sources, d'où la gravité Moyenne.

## Correction (rempli par le défenseur)

- Fichiers modifiés : `backend/plugins/revision/sources.py` (`pdf_text`, suppression de `_public_host`), `backend/dao/safe_http.py`
- Principe : `pdf_text` passe par `safe_http.get()` : le nom est résolu une seule fois, l'adresse vérifiée est celle à laquelle on se connecte (plus de seconde résolution par `requests`, donc plus de rebinding DNS). URL refusée ou trop grosse → chaîne vide ; panne réseau → `SafeHttpError` (sous-classe de `requests.RequestException`, déjà gérée par l'appelant).
