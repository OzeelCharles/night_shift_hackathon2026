# F-10 — KaTeX chargé depuis cdnjs sans integrity (SRI)

- **Gravité** : Basse
- **Exigence** : SEC-09
- **Trouvée par** : attaquant, manche 3, le 2026-11-27
- **Route / fichier** : `backend/plugins/revision/templates/revision/_style.html:67-69`
- **Statut** : reproduit

## Reproduction

Les trois ressources KaTeX (`katex.min.css`, `katex.min.js`, `auto-render.min.js`) viennent de
`cdnjs.cloudflare.com` sans attribut `integrity` ni `crossorigin`.

Impact : si le CDN (ou le chemin jusqu'à lui) est compromis, un script arbitraire s'exécute dans les pages de
l'atelier de révision, avec la session de l'élève.

Résultat attendu : `integrity="sha384-…"` et `crossorigin="anonymous"` sur chaque ressource externe, ou copie locale
dans `frontend/static/`. (Les polices Google, CSS générée à la volée, sont hors de ce test.)

## Correction (rempli par le défenseur)

- Fichiers modifiés : `backend/plugins/revision/templates/revision/_style.html`, `frontend/static/js/katex-init.js` (nouveau)
- Principe : les 3 ressources KaTeX 0.16.9 de cdnjs portent `integrity="sha384-…"`, `crossorigin="anonymous"` et `referrerpolicy="no-referrer"`. Le lancement du rendu (ancien attribut `onload=`) est passé dans un script local différé. À vérifier avec accès réseau : les empreintes sont celles que publie KaTeX pour la 0.16.9, je n'ai pas pu les recalculer (aucun réseau externe). Commande : `curl -s <url> | openssl dgst -sha384 -binary | openssl base64 -A`. Une empreinte fausse bloquerait KaTeX : les formules resteraient affichées en LaTeX brut, sans autre effet.
